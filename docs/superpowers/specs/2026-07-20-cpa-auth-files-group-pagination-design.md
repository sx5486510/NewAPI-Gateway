# CPA 认证文件分组独立分页设计

**日期：** 2026-07-20  
**状态：** 已批准

## 背景

Gateway 的 CPA 认证文件页面通过官方 `/v0/management/auth-files` 接口一次获取认证文件，并在前端按 provider 分为 Antigravity、Claude、Codex、Kimi、Grok 和其他六组。当前每组会一次渲染全部文件，并为全部文件下载认证详情。文件数量较多时，页面渲染和详情请求都会持续增长。

本次改动为每个非空分组提供相互独立的客户端分页。每组默认每页 50 条，可选择 20、50 或 100 条，并只加载当前可见页的认证详情。

## 目标

- 每个 provider 分组独立维护当前页码和每页条数。
- 每组默认每页 50 条，可选 20、50、100 条。
- 一个分组的翻页或每页条数变更不影响其他分组。
- 只渲染各组当前页的文件，并只下载这些可见文件的认证详情。
- 保持现有 CPA 官方管理接口、Gateway 代理和认证文件操作不变。

## 非目标

- 不向 CPA 或 Gateway 后端增加分页参数或自定义分页接口。
- 不改变 provider 分组规则或分组显示顺序。
- 不改变上传、下载、编辑、启用、禁用、删除、额度查询和冷却重置的业务行为。
- 不增加服务端缓存或持久化用户的分页偏好。

## 方案选择

采用客户端分组独立分页，并按可见页惰性加载认证详情。

未采用以下方案：

- 仅分页渲染但继续下载全部认证详情：改动较小，但不能降低大量文件产生的详情请求。
- 在 Gateway 代理层扩展服务端分组分页：会偏离官方 `/auth-files` 契约，并增加后端协议和维护成本。

## 状态设计

`CPAAuthFiles` 按固定分组 key 保存两组状态：

- `pageByGroup`：每组当前页码，页码从 1 开始，缺省值为 1。
- `pageSizeByGroup`：每组每页条数，缺省值为 50。

每页条数只允许 20、50、100。用户修改某组每页条数时，仅将该组页码重置为 1，其他组状态保持不变。

认证文件列表变化后，每组当前页码必须收敛到 `1..totalPages`。空分组不渲染，也不需要分页状态；非空分组的 `totalPages` 至少为 1。这样在删除、上传或刷新导致数据数量变化时，不会显示超出范围的空白页。

## 数据流

1. 页面继续调用 `/v0/management/auth-files` 获取完整列表。
2. 使用现有 provider 识别规则把列表分为六组。
3. 根据各组的页码和每页条数计算当前页切片。
4. 渲染所有非空分组，但每组只渲染其当前页切片。
5. 汇总所有分组当前页可见文件，作为认证详情加载队列。
6. 详情加载继续使用最多四个并发 worker。
7. 已成功或失败完成的文件详情按文件名缓存；切换分页时只请求尚未缓存的可见文件。
8. 列表刷新开始新的加载代次，旧代次的异步结果不得覆盖新列表状态。

列表刷新会保留仍存在文件的详情缓存，删除已不在列表中的缓存项，并为新出现且当前可见的文件加载详情。文件名是现有接口与页面操作使用的稳定标识，本设计继续以文件名作为缓存 key。

## 界面设计

每个非空分组底部显示独立分页栏：

- 左侧显示该分组总数：`共 N 条`。
- 中间显示原生选择器：`每页 20 / 50 / 100 条`，默认选中 50。
- 右侧复用现有 `web/src/components/ui/Pagination.js`。

当分组只有一页时，现有 `Pagination` 自动隐藏页码按钮，但总数和每页条数选择器仍显示。分组标题的数量徽标继续表示该分组总数。

翻页只更新目标分组，不主动滚动页面，也不重置其他分组。选择新的每页条数后，目标分组回到第 1 页。

## 组件边界

改动限定在：

- `web/src/components/CPAAuthFiles.js`
- `web/src/components/CPAAuthFiles.test.js`

复用：

- `web/src/components/ui/Pagination.js`
- 现有 Button、Card 和认证详情并发加载辅助函数。

分页计算使用小型纯函数完成页数计算、页码收敛和数组切片，以便直接测试并避免把分页规则散落在 JSX 中。本次不拆分认证文件行或新增通用分页框架。

## 错误与边界处理

- 单个认证详情下载失败仍只在对应文件行显示安全错误，不影响其他文件或分组。
- 列表请求失败沿用现有错误提示，并保留页面当前已有列表和分页状态。
- 当前页因删除而越界时，自动切换到新的最后一页。
- 页面切换期间到达的旧详情响应必须通过加载代次检查，不能写入新列表状态。
- 选择器只产生受支持的数值；状态计算仍对无效值回退到默认 50，避免异常状态破坏切片范围。

## 测试策略

按测试驱动方式增加前端组件测试，先验证测试因分页能力缺失而失败，再实现最小改动。

覆盖以下行为：

- 单组超过 50 条时默认只显示前 50 条。
- 每组默认选择 50，且选项为 20、50、100。
- 两个分组的页码相互独立。
- 两个分组的每页条数相互独立。
- 修改某组每页条数后，仅该组回到第 1 页。
- 列表数据减少后，越界页码收敛到最后一个有效页。
- 初始只下载各组当前页可见文件的认证详情。
- 翻页加载新可见文件，切回已加载页不重复下载详情。
- 过期的详情异步响应仍会被忽略。
- 现有上传、下载、编辑、状态切换、删除、额度、冷却重置和刷新测试继续通过。

验证命令以仓库现有 React 测试脚本为准，至少执行 `CPAAuthFiles.test.js` 定向测试，并执行相关前端测试或构建检查确认无回归。
