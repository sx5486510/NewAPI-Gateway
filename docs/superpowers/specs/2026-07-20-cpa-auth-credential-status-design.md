# CPA 认证凭据状态展示设计

## 目标

Gateway 的 CPA 认证文件页面为每个认证文件展示三类诊断信息：最近刷新时间、Access Token 到期状态，以及 Refresh Token 状态。页面帮助管理员定位 401 和长期未刷新问题，但不主动交换、轮换或修改任何 Token。

实现必须复用 CPA v7.2.80 的官方管理接口：

- `GET /v0/management/auth-files` 获取认证列表和 `last_refresh`、`status`、`status_message` 等运行时状态。
- `GET /v0/management/auth-files/download?name=<file>` 读取当前管理员有权下载的认证 JSON，并在浏览器内派生非敏感状态。

Gateway 不新增认证状态后端接口，不把 Token 写入 Gateway 状态，也不记录或显示 Token 内容。

## 字段语义

### 最近刷新

`last_refresh` 直接使用认证列表接口的返回值。CPA SDK 将它定义为最近一次成功刷新的 UTC 时间；首次授权也可能初始化该字段，因此页面将其作为诊断时间，而不是凭据当前有效的证明。

有效时间显示为本地化日期时间；缺失或无法解析时显示“未知”。页面可以附带相对时间，但完整时间必须可见。

### Access Token 到期状态

CPA v7.2.80 的 xAI、Claude、Codex、Kimi 和 Antigravity 认证文件都使用 RFC3339 字符串字段 `expired` 保存 Access Token 到期时间。页面只解析该官方字段：

- 到期时间晚于当前时间：显示“有效至 <本地时间>”。
- 到期时间等于或早于当前时间：显示“已过期（<本地时间>）”。
- 字段缺失、为空或无法解析：显示“未知”。

状态是页面渲染时的快照。它不触发 Token 刷新，也不代表账号或 Refresh Token 一定可用。

### Refresh Token 状态

页面只检查官方字段 `refresh_token` 是否为非空字符串，绝不保留或渲染其值。状态规则为：

- 字段缺失或空白：`缺失`。
- 字段存在，且没有失败证据：`存在但未验证`。
- 字段存在，同时认证列表的 `status`、`status_message`，或本次页面会话中的真实额度查询结果明确表明 HTTP 401/unauthorized：`疑似失效`。

“疑似失效”优先于“存在但未验证”。由于本功能不执行 OAuth 刷新交换，因此不显示“有效”，避免把字段存在或历史刷新成功误报为当前有效。

## 前端结构

在 `CPAAuthFiles` 的每个认证文件行中增加紧凑的“认证状态”区域，和现有文件信息、真实额度信息并列展示。区域包含固定的三个标签：

- 最近刷新
- Access Token
- Refresh Token

列表接口返回后立即展示最近刷新；凭据详情尚未获取时，另外两个字段显示“读取中”。详情读取成功后只把派生结果写入 React state，原始 JSON 和 Token 值不进入 state。

凭据解析和状态推导放入独立的纯函数模块，组件只负责请求、并发控制和渲染。这样可以单独测试时间边界和状态优先级，避免继续扩大 `CPAAuthFiles.js` 的职责。

## 数据流与并发

1. 页面调用官方认证列表接口并更新认证文件列表。
2. 页面为列表中的文件调用官方下载接口，使用现有 `mapWithConcurrency`，并发上限为 4。
3. 每个响应立即解析为 `{ accessExpiry, accessStatus, refreshStatus }` 等非敏感字段；函数返回前丢弃原始对象。
4. 单个文件下载或解析失败只更新该文件的详情错误，不中断其他文件。
5. 点击“刷新列表”时开始新一轮请求。旧轮次的迟到结果不得覆盖新列表，已从列表删除的文件不得重新写回状态。

下载请求只对已经由官方列表返回、且名称非空的条目发出。文件名继续通过 Axios `params` 传递，不手工拼接 URL。

## 错误与安全处理

- 下载失败显示“无法读取认证详情”，不推断为 Token 缺失或失效。
- JSON 无法解析显示“认证文件格式无效”，不显示响应片段。
- `expired` 无法解析时只显示“未知”，不默认判定为已过期。
- 真实额度请求的错误只有在明确包含 HTTP 401 或 unauthorized 语义时才影响 Refresh Token 状态；网络错误、502、超时和其他 provider 错误不影响该状态。
- 测试、日志、Toast、DOM、React state 和错误消息都不得包含 `access_token`、`refresh_token` 或 `id_token` 的值。
- 本功能只读，不调用 OAuth refresh，不修改认证文件，不增加 Gateway 持久化。

## 测试与验收

纯函数测试覆盖：

- RFC3339 `expired` 的未过期、刚好过期、已过期、缺失和非法值。
- `refresh_token` 缺失、空白和存在。
- 401/unauthorized 证据把存在的 Refresh Token 标为“疑似失效”。
- 非 401 错误不会把 Refresh Token 标为“疑似失效”。
- 派生结果不包含任何 Token 值。

组件测试覆盖：

- `last_refresh` 直接来自列表接口并正确显示。
- 官方下载接口以 `name` 参数调用，成功后展示三项状态。
- 多文件详情读取并发数不超过 4。
- 单文件下载失败不影响其他认证文件。
- 刷新列表后，旧请求结果不会覆盖新一轮状态。
- 真实额度查询返回 401 后，对应行显示 Refresh Token“疑似失效”。
- DOM 和用户可见错误中不出现测试 Token 值。
- 现有额度查询、冷却重置、上传、编辑、启停、下载和删除行为不回归。

验收时运行相关 Jest 测试、完整前端测试套件、生产构建和 `git diff --check`。
